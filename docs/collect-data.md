# Сбор диагностических данных с клавиатур

> **Кому:** владельцам **AULA F99** (NixOS) и **Ajazz AK820 Pro** (Fedora), у которых есть реальное железо и которые хотят помочь проекту Keyboard-Center.
>
> **Зачем:** у разработчика эти две модели физически отсутствуют — драйверы под них написаны по протокольным аналогам и ресёрчу и ещё не проверялись на реальных клавиатурах. Ваши снимки данных позволят подтвердить или поправить драйверы и сканер.
>
> **ВАЖНО: в этом документе только ЧТЕНИЕ.** Никакие команды не пишут в память клавиатуры и не меняют её настройки. Запись в чужую клавиатуру исключена.

---

## 1. Установка утилиты `kbc`

Утилита `kbc` входит в этот репозиторий и работает в режиме командной строки.

### Вариант A — NixOS (для владельца AULA F99)

```bash
# из каталога репозитория — собрать и побыть в dev-shell с зависимостями
cd keyboard-control
nix develop . --command cargo build --release

# бинарники появятся в target/release/kbc и target/release/keyboard-center
```

Либо подключить репозиторий как флейк (NixOS-модуль) — тогда `kbc` появится в PATH (см. README, Вариант 1).

Чтобы `kbc` открывал устройства без root — нужен доступ к `/dev/hidraw`:

```bash
# добавить пользователя в группу plugdev (нужен перелогин)
sudo usermod -aG plugdev $USER
# быстрый вариант без перелогина:
sg plugdev -c "kbc list"
```

### Вариант B — Fedora (для владельца Ajazz AK820 Pro)

```bash
# зависимости для сборки (dnf)
sudo ./fedora_install.sh --install-deps

# собрать release
make release

# установить на уровне пользователя (без sudo) — бинарники, .desktop, иконка
./fedora_install.sh --user

# + udev-правила под доступ к hidraw (см. README, Вариант 5, Шаг 4)
sudo ./fedora_install.sh --udev-only
```

> [!NOTE]
> После установки udev-правил или добавления в группу `plugdev` нужен перелогин, либо оборачивайте команды в `sg plugdev -c "…"`.

## 2. Сбор данных с AULA F99 (NixOS)

F99 — это SinoWealth SH68F90, протокол общий с F75. От вас нужно подтвердить на реальном железе:

1. сканер видит клавиатуру;
2. разведка интерфейсов/usage pages совпадает с ожидаемой;
3. снимок конфиг-региона (520 байт, маркер `5A A5`);
4. некоторые идентификаторы (модель, PID).

### Шаг 2.1. Сканер

```bash
kbc list
# или через sg plugdev, если ещё не перелогинились:
sg plugdev -c "kbc list"
```

Ожидаем увидеть строку с `258A:004E` (USB) или `258A:004F` (2.4G-ресивер):

```
AULA F99 258A:004E
```

### Шаг 2.2. Информация об устройстве

```bash
kbc info 258A:004E
```

### Шаг 2.3. Разведка интерфейсов (ключевой шаг)

```bash
kbc probe 258A:004E
```

Ожидаем: несколько интерфейсов hidraw, один из них «вендорский» с `usage_page >= 0xFF00` (командный канал). Именно его должен выбирать драйвер.

### Шаг 2.4. Дамп конфиг-региона (главный запрос)

Клавиатура AULA отвечает на feature-запрос `06 84 …` полным 520-байтовым пакетом. Порядок: сначала `feature-send`, затем `feature-get`.

```bash
kbc raw 258A:004E feature-send "06 84 00 00 01 00 80 00"
kbc raw 258A:004E feature-get 06 520
```

Ожидаем: ответ, начинающийся с `06 84 …` и заканчивающийся маркером `5A A5`. Сохраните вывод в файл:

```bash
kbc raw 258A:004E feature-get 06 520 > f99_config_dump.txt
```

### Шаг 2.5. Чтение таблицы цветов (пери-кей) — если получится

```bash
kbc raw 258A:004E feature-send "06 8a 00 00 01 00 00 02"
kbc raw 258A:004E feature-get 06 520 > f99_color_table.txt
```

> [!NOTE]
> На проводном F75 этот адрес раньше давал Protocol error — если на F99 тот же результат, это ценная информация (протокольная несовместимость), просто запишите вывод.

### Шаг 2.6. Батарея (только 2.4G-ресивер)

```bash
# переключите клавиатуру на 2.4G-ресивер 3554:FA09, разбудите нажатием клавиши
kbc battery 3554:FA09
```

Ожидаем: `батарея: N%`.

### Шаг 2.7. Системная информация

```bash
lsusb
udevadm info --attribute-walk /dev/hidraw<номер> | grep -E "idVendor|idProduct|usage_page|interface_number" 2>/dev/null
```

Приложите вывод `lsusb` для `258A:004E/004F` и содержимое uevent командного hidraw.

## 3. Сбор данных с Ajazz AK820 Pro (Fedora)

Ajazz AK820 Pro — Sonix SN32F299 (wsclx-протокол). От вас нужно подтвердить:

1. сканер видит клавиатуру (ревизия 0x8009 / 0x800A / 0x8099);
2. разведка интерфейсов/usage pages совпадает (control 0xFF13, data 0xFF68);
3. батарея читается;
4. идентификатор устройства.

### Шаг 3.1. Сканер

```bash
kbc list
```

Ожидаем: `Ajazz AK820 Pro 0C45:8009` (или 800A / 8099).

### Шаг 3.2. Информация об устройстве

```bash
kbc info 0C45:8009
```

### Шаг 3.3. Разведка интерфейсов (ключевой шаг)

```bash
kbc probe 0C45:8009
```

Ожидаем: среди интерфейсов есть usage pages `0xFF13` (control-канал команд) и `0xFF68` (data-канал настройки подсветки). Расхождение с ожидаемым — важный сигнал, что ревизия/прошивка другая.

### Шаг 3.4. Батарея

```bash
kbc battery 0C45:8009
```

Ожидаем: `батарея: N%` (у Ajazz заряд читается, в отличие от AULA по USB).

### Шаг 3.5. Чтение текущего пресета RGB (если поддерживается драйвером)

```bash
kbc rgb 0C45:8009 --mode spectrum --hold 100
```

> [!WARNING]
> Это команда **прямого кадра** (host-rendering, на лету), а не запись в память — она не сохраняет настройки. Если сомневаетесь — пропустите.

> [!IMPORTANT]
> НЕ выполняйте `kbc save` / `kbc rgb --light-on` / `kbc rgb --light-off` — это запись в память. В рамках этого сбора — только чтение.

### Шаг 3.6. Системная информация

```bash
lsusb
udevadm info --attribute-walk /dev/hidraw<номер> | grep -E "idVendor|idProduct|usage_page|interface_number" 2>/dev/null
```

Приложите вывод `lsusb` для `0C45:8009` (и содержимое uevent командного hidraw).

## 4. Что и куда прислать

Соберите в один файл/архив (или просто вставьте вывод в чат) следующие данные:

| # | Команда | Файл/секция |
|---|---|---|
| 1 | `kbc list` | `kbc_list.txt` |
| 2 | `kbc info <vid:pid>` | `kbc_info.txt` |
| 3 | `kbc probe <vid:pid>` | `kbc_probe.txt` |
| 4 | дамп конфига (F99) / батарея (Ajazz) | `f99_config_dump.txt` / `kbc_battery.txt` |
| 5 | `lsusb` | `lsusb.txt` |
| 6 | uevent командного hidraw | `uevent.txt` |

Если какой-то шаг дал неожиданный результат (ошибка, другой PID, другой usage page) — обязательно приложите вывод: это не «провал», а ценная информация для поправки драйвера.

**Куда отправлять:** в этот же репозиторий (issue / комментарием) или в чат проекта — на усмотрение владельца.

---

## 5. Важные предостережения

- **Не запускайте команды записи** (`kbc save`, `kbc rgb --light-off/--light-on`, `kbc set-*`, `kbc time`, `kbc screen`) — этот сбор не меняет настроек клавиатуры.
- **Не отключайте** клавиатуру во время `feature-get` — драйвер держит канал открытым.
- Если после команды клавиатура «переподключилась» (узлы hidraw исчезли на 1–2 сек) — это штатное поведение AULA на некоторых write, но в рамках этого документа записей не выполняем, так что такого быть не должно.
- Данные клавиатуры исторические и к колонке «BT» отношения не имеют: **по Bluetooth (BT) проект ничего не обещает** — единственный живой канал батареи это 2.4G-ресивер.
