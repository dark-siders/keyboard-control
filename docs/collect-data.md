# Сбор диагностических данных с клавиатур

> **Кому:** владельцам **AULA F99** (NixOS) и **Ajazz AK820 Pro** (Fedora), у которых есть реальное железо и которые хотят помочь проекту Keyboard-Center.
>
> **Зачем:** у разработчика нет локального железа F99 и Ajazz; F99 уже проверен на отдельном реальном устройстве, но дополнительные каналы всё ещё требуют подтверждения. Ajazz ревизии `0C45:8009` проверен на живом железе (журнал 10.106/10.114/10.115): подсветка, время, сон, заряд и per-key идут через control-канал `0xFF13`, а wsclx `0xFF68` (TFT) на этой ревизии **не отвечает**; keymap и макросы, по реверсу официального ПО, тоже живут на `0xFF13` (`0x11`/`0x27`, `0x19`/`0x15`); макросы уже переведены (`kbc macro --set`, без живой проверки), keymap ещё ждёт переноса. Сводка — `docs/ajazz-guide.md`, раздел A. Ваши снимки данных позволят подтвердить или поправить драйверы и сканер.
>
> **ВАЖНО: по умолчанию в этом документе только ЧТЕНИЕ.** Основной сбор не пишет в память клавиатуры и не меняет её настройки. Запись в чужую клавиатуру исключена. **Единственное исключение** — для владельцев **AULA F99**: скрипт `collect-data.sh` с флагом `--write-tests` делегирует write-тесты T1–T6 в `scripts/f99-usb-rev.sh` (каждый тест запрашивает подтверждение и **восстанавливает исход**). Запускайте его только если готовы к кратковременной записи в память клавиатуры (подробно см. `docs/f99-guide.md`, секция B2.10).
>
> **Ajazz AK820 Pro:** для него есть отдельный read-only гайд и скрипт — `docs/ajazz-guide.md` и `scripts/ajazz-usb-diag.sh` (только GET-команды, в т.ч. `kbc ajazz-diag`). Для Ajazz write-тестов пока НЕТ.

## 0. Быстрый способ: скрипт `scripts/collect-data.sh`

Самый простой вариант — запустить готовый скрипт: он сам выполнит все шаги из этого документа и упакует результат.

```bash
# 1. скопируйте репозиторий (или клонируйте) и соберите kbc один раз (см. раздел 1),
#    затем:
./scripts/collect-data.sh
# для клавиатуры в режиме 2.4G/ресивера или если группа plugdev ещё не применилась:
./scripts/collect-data.sh --sg
# явно указать модель, если автодетект не сработал:
./scripts/collect-data.sh --device f99
./scripts/collect-data.sh --device ajazz
# для Ajazz AK820 Pro есть отдельный read-only сбор (только GET + kbc ajazz-diag):
./scripts/ajazz-usb-diag.sh --sg
# ТОЛЬКО для AULA F99: включить write-тесты T1–T6 (скрипт сам вызовет scripts/f99-usb-rev.sh;
# каждая запись подтверждается по Y/N и после теста восстанавливается):
./scripts/collect-data.sh --device f99 --sg --write-tests
```

Скрипт: определяет клавиатуру по `kbc list`, собирает info/probe/battery и дампы конфига **и таблицы цветов**, **keymap Default/FN1** и **интерактивный дифф** (индикаторы) для F99, кладёт **читаемую карту keymap** (`kbc remap --list`, Default+FN1) для F99 и Ajazz, добавляет `lsusb` и uevent, кладёт всё в папку **`~/kbc-diag-ГГГГММДД-ЧЧММСС/`** (пример: `~/kbc-diag-20260917-231500/`) и упаковывает её в одноимённый архив **`~/kbc-diag-ГГГГММДД-ЧЧММСС.tar.gz`**.

> [!IMPORTANT]
> **Имя папки с результатами — `~/kbc-diag-ГГГГММДД-ЧЧММСС/`** (без существующего каталога `~` — у вас в домашней директории). Архив — рядом, `~/kbc-diag-ГГГГММДД-ЧЧММСС.tar.gz`. Отправьте именно этот `.tar.gz`.

По умолчанию скрипт выполняет **только чтение** — он не запускает `kbc save` / `kbc rgb --light-*` / `kbc set-*` / `kbc time` / `kbc screen`. Единственное исключение — флаг `--write-tests` **только для AULA F99** (см. пример выше и абзац о `f99-usb-rev.sh` ниже): write-тесты включаются лишь явным флагом и после каждого восстанавливают исход.

> **Для AULA F99 есть второй, более глубокий скрипт — `scripts/f99-usb-rev.sh`.** Он собирает тот же read-only набор (дампы конфига/цветов/keymap, probe, lsusb) и дополнительно умеет **write-тесты T1–T6** с флагом `--write-tests` (запись конфига `06 04`, индикаторы через boot output-report, поиск селектора self-define `data[10]` в color table, keymap write, per-key color write, indicators config diff). Каждый тест после себя **восстанавливает исход** и требует подтверждения перед выполнением. Подробности — в `docs/f99-guide.md` (секция B2.10). Выполняйте его только если готовы к кратковременной записи в память клавиатуры.

## 1. Установка утилиты `kbc`

Утилита `kbc` входит в этот репозиторий и работает в режиме командной строки.

### Вариант A — NixOS (для владельца AULA F99)

```bash
# из каталога репозитория — собрать и побыть в dev-shell с зависимостями
cd keyboard-control
nix develop . --command cargo build --release

# бинарники появятся в target/release/kbc и target/release/keyboard-center
```

Либо подключить репозиторий как флейк (NixOS-модуль) — тогда `kbc` появится в PATH (см. [docs/install.md](install.md), Вариант 1).

Чтобы `kbc` открывал устройства без root — нужен доступ к `/dev/hidraw`:

```bash
# добавить пользователя в группу plugdev (нужен перелогин)
sudo usermod -aG plugdev $USER
# быстрый вариант без перелогина:
sg plugdev -c "kbc list"
```

### Вариант B — Fedora (для владельца Ajazz AK820 Pro)

```bash
# зависимости для сборки (dnf)
sudo ./fedora.sh deps

# собрать release
make release

# установить на уровне пользователя (без sudo) — бинарники, .desktop, иконка
./fedora.sh install --user

# + udev-правила под доступ к hidraw (см. docs/install.md, Вариант 5, Шаг 3)
sudo ./fedora.sh install --udev-only
```

> [!NOTE]
> После установки udev-правил или добавления в группу `plugdev` нужен перелогин, либо оборачивайте команды в `sg plugdev -c "…"`.

## 2. Сбор данных с AULA F99 (NixOS)

F99 — это SinoWealth SH68F90, протокол общий с F75. От вас нужно подтвердить на реальном железе:

1. сканер видит клавиатуру;
2. разведка интерфейсов/usage pages совпадает с ожидаемой;
3. снимок конфиг-региона (520 байт, маркер `5A A5`);
4. некоторые идентификаторы (модель, PID);
5. **читается ли канал keymap** (ремап F99 у нас не ревёрснут — это главный открытый вопрос);
6. **где живут индикаторы** (Caps/Num/Scroll) в конфиге (у F99 ролика/энкодера НЕТ).

> [!IMPORTANT]
> **F75 и F99 — один USB PID `258A:010C`.** Различаются они только моделью в дампе прошивки: `0xA4` = F99 (`0xcd/0xe1/0x91` = F75 по ревизиям). Модель определяется через `kbc info`. Поэтому:
> * в `kbc list` строка может выглядеть как `AULA F75 258A:010C USB` — это НЕ ошибка, а физическая F99;
> * реальную модель смотрите в `kbc info` — там «Модель: AULA F99».

### Шаг 2.1. Сканер

```bash
kbc list
# или через sg plugdev, если ещё не перелогинились:
sg plugdev -c "kbc list"
```

Пример с реальной F99 (журнал 10.70):

```
AULA F75 258A:010C USB
AULA F75 (2.4 GHz) 3554:FA09
```

Есть и ревизии F99 с PID `258A:004E` (USB) / `258A:004F` (2.4G-ресивер) — тоже валидный вариант.

### Шаг 2.2. Информация об устройстве

PID берём из `kbc list` (у реальной F99 — `258A:010C`):

```bash
kbc info 258A:010C
```

Ожидаем строку `Модель: AULA F99 (USB)` — именно она подтверждает модель (см. блок above).

### Шаг 2.3. Разведка интерфейсов (ключевой шаг)

```bash
kbc probe 258A:010C
```

Ожидаем: несколько интерфейсов hidraw, один из них «вендорский» с `usage_page >= 0xFF00` (командный канал). Именно его должен выбирать драйвер.

### Шаг 2.4. Дамп конфиг-региона (главный запрос)

Клавиатура AULA отвечает на feature-запрос `06 84 …` полным 520-байтовым пакетом. Порядок: сначала `feature-send`, затем `feature-get`.

> [!IMPORTANT]
> Клавиатура ждёт именно **полный пакет из 520 байт** — короткий SET из 8 байт проходит, но ответа на `feature-get` не будет. Полный пакет: заголовок `06 84 00 00 01 00 80 00` + 512 нулевых байт. Скрипт `collect-data.sh` делает паддинг автоматически; вручную сгенерируйте командой:
>
> ```bash
> FULL=$(printf '06 84 00 00 01 00 80 00 '; yes '00' | head -512)
> kbc raw 258A:010C feature-send "$FULL"
> kbc raw 258A:010C feature-get 06 520
> ```

Ожидаем: ответ, начинающийся с `06 84 …` и заканчивающийся маркером `5A A5`. Сохраните вывод в файл:

```bash
kbc raw 258A:010C feature-get 06 520 > f99_config_dump.txt
```

> [!NOTE]
> В конфиг-регионе селектор эффекта — байт `data[10]`, слоты эффектов — пары `(a=яркость, b=speed|color)` в `data[58..125]` (у F99 их **34 пары**, как у F75-ресивера; у USB-F75 было 20 пар `[58..96]`).

### Шаг 2.5. Чтение таблицы цветов (пери-кей) — если получится

```bash
FULL=$(printf '06 8a 00 00 01 00 00 02 '; yes '00' | head -512)
kbc raw 258A:010C feature-send "$FULL"
kbc raw 258A:010C feature-get 06 520 > f99_color_table.txt
```

> [!NOTE]
> **На живой F99 таблица цветов ЧИТАЕТСЯ** (журнал 10.70): 512 байт = 128 записей `RR GG BB XX`. В хвосте региона лежит не цвет, а трейлер: маркер модели `A4 01` (=0xA4 — подтверждает F99), `00 00 5A A5`, хвост. На проводном F75 этот же адрес давал Protocol error — расхождение каналов, если увидите аналогичное — запишите вывод как есть.

### Шаг 2.6. Дампы keymap (ремап F99 — главный открытый вопрос)

У **F75** ремап ревёрснут и реализован (`kbc remap`, 512-байтная таблица 128 слотов Default+FN1, журнал 10.62). У **F99** тот же канал ещё НЕ проверен — если он читается, ремап можно включить и для F99. Проверяется read-only запросом `06 83 …` (write-команда `0x03` в этом сборе не используется):

```bash
# слой 0 (Default):
FULL=$(printf '06 83 00 00 01 00 00 02 '; yes '00' | head -512)
kbc raw 258A:010C feature-send "$FULL"
kbc raw 258A:010C feature-get 06 520 > f99_keymap_default.txt

# слой 1 (FN1 — байт [3]=01):
FULL=$(printf '06 83 00 01 01 00 00 02 '; yes '00' | head -512)
kbc raw 258A:010C feature-send "$FULL"
kbc raw 258A:010C feature-get 06 520 > f99_keymap_fn1.txt
```

> [!IMPORTANT]
> Ожидаем 520-байтный ответ вида `06 83 <слой> … 5A A5`. Если приходит `Protocol error` или пустой ответ — **это сам по себе результат**: он означает, что канал ремапа у F99 отличается и ремап придётся ревёрсить отдельно. Приложите вывод как есть.

### Шаг 2.7. Интерактивный дифф конфига (индикаторы)

Индикаторы (Caps/Num/Scroll) у F99 **не ревёрснуты** — мы не знаем, в каких байтах конфиг-региона они живут (ролика/энкодера у F99 нет). Чтобы их найти, снимаем конфиг **дважды**: до и после действий на клавиатуре, затем сравниваем. Это **только чтение** — вы лишь нажимаете кнопки на клавиатуре, в память ничего не пишется.

```bash
# снимок ДО:
FULL=$(printf '06 84 00 00 01 00 80 00 '; yes '00' | head -512)
kbc raw 258A:010C feature-send "$FULL"
kbc raw 258A:010C feature-get 06 520 > f99_cfg_before.txt

# --- теперь на САМОЙ КЛАВИАТУРЕ (не на ПК!): ---
#   1) нажмите-отпустите Caps Lock, затем Num Lock, затем Scroll Lock.

# снимок ПОСЛЕ:
kbc raw 258A:010C feature-send "$FULL"
kbc raw 258A:010C feature-get 06 520 > f99_cfg_after.txt

# разница (только отличающиеся байты):
diff -u f99_cfg_before.txt f99_cfg_after.txt   # либо: cmp -l f99_cfg_before.txt f99_cfg_after.txt
```

> [!NOTE]
> В скрипте `collect-data.sh` этот шаг интерактивный — он сам попросит совершить действия и подождёт Enter. Если дифф пуст — значит индикаторы в конфиг-регионе не отражаются (тоже полезный ответ).

### Шаг 2.8. Батарея (только 2.4G-ресивер)

```bash
# переключите клавиатуру на 2.4G-ресивер 3554:FA09, разбудите нажатием клавиши
kbc battery 3554:FA09
```

Ожидаем: `батарея: N%`.

### Шаг 2.9. Системная информация

```bash
lsusb
udevadm info --attribute-walk /dev/hidraw<номер> | grep -E "idVendor|idProduct|usage_page|interface_number" 2>/dev/null
```

Приложите вывод `lsusb` для `258A:010C` (или `004E/004F`) и содержимое uevent командного hidraw.

## 3. Сбор данных с Ajazz AK820 Pro (Fedora)

Ajazz AK820 Pro — Sonix SN32F299. **На ревизии `0C45:8009` уже проверено (2026-11-11):** подсветка (20 режимов), синк времени, сон и заряд АКБ работают через control-канал `0xFF13` (feature, 65-байтовый буфер = `0x00` + 64); per-key (`0x23`/`0x20`) реализован по реверсу официального ПО и ждёт живой проверки. **Не отвечает** wsclx `0xFF68` — поэтому TFT на этой ревизии недоступен; keymap (`0x11`/`0x27`) по реверсу живёт на `0xFF13`, но код ещё не переведён; макросы (`0x19`/`0x15`) переведены и доступны через `kbc macro --set` (на железе не проверено; чтения keymap/макросов нет). Сводная таблица — `docs/ajazz-guide.md`, раздел A.

От вас нужно подтвердить (в первую очередь для **других ревизий** — `0x800A`, `0x8099` — и новых прошивок):

1. сканер видит клавиатуру (ревизия 0x8009 / 0x800A / 0x8099);
2. разведка интерфейсов/usage pages совпадает (control 0xFF13, data 0xFF68, TFT 0xFF67);
3. батарея читается через `0xFF13`;
4. идентификатор устройства;
5. **отвечает ли транспорт `0xAA`/`0x55`** на GET-команды — на 8009 ответ «нет», интересно, как на других ревизиях (см. `kbc ajazz-diag`).

> [!TIP]
> Быстрее и полнее — отдельный скрипт **`./scripts/ajazz-usb-diag.sh`** (read-only): он выполняет шаги 3.1–3.6 ниже плюс `kbc ajazz-diag` и `kbc remap --list`, и упаковывает всё в `~/kbc-diag-ajazz-*.tar.gz`. Подробности — `docs/ajazz-guide.md`.

### Шаг 3.1. Сканер

```bash
kbc list
```

Ожидаем: `Ajazz AK820 Pro 0C45:8009` (или 800A / 8099).

### Шаг 3.2. Информация об устройстве

```bash
kbc info 0C45:8009
```

### Шаг 3.3. Разведка интерфейсов (ключевой шаг)

```bash
kbc probe 0C45:8009
```

Ожидаем: среди интерфейсов есть usage pages `0xFF13` (control-канал команд) и `0xFF68` (data-канал настройки подсветки). **На проверенной ревизии 8009:** 4 интерфейса — boot-клавиатура, consumer/system, `0xFF68`, `0xFF13`; TFT `0xFF67` отсутствует. Расхождение с ожидаемым — важный сигнал, что ревизия/прошивка другая.

### Шаг 3.4. Батарея

```bash
kbc battery 0C45:8009
```

Ожидаем: `батарея: N%`. Заряд читается через control-канал `0xFF13` (пакет `0x20 0x01`, уровень в 4-м байте ответа) — на ревизии 8009 это реализовано по реверсу официального ПО и ждёт подтверждения. Если пришло «батарея по USB не читается» — приложите вывод как есть.

### Шаг 3.5. Чтение текущего пресета RGB (если поддерживается драйвером)

```bash
kbc rgb 0C45:8009 --mode spectrum --hold 100
```

> [!WARNING]
> Это команда **живого кадра**, а не запись в память: у AULA она идёт host-рендерингом, у Ajazz применяется аппаратно через control-канал `0xFF13`. В энергонезависимую память ничего не сохраняется. Если сомневаетесь — пропустите.

> [!IMPORTANT]
> НЕ выполняйте `kbc save` / `kbc rgb --light-on` / `kbc rgb --light-off` — это запись в память. В рамках этого сбора — только чтение.

### Шаг 3.5b. Read-only дамп протокола `kbc ajazz-diag` (главный шаг)

```bash
kbc ajazz-diag 0C45:8009 > ajazz_diag.txt
# читаемая карта keymap (Default+FN1):
kbc remap 0C45:8009 --list > ajazz_keymap_list.txt
```

Команда выполняет **только GET-команды** (device-info, LED-эффект, game-mode, custom-LED буфер, keymap Default/FN1 + заводские матрицы, макросы) и печатает `ключ=hex` по строке на секцию; при ошибке команды — `ключ_error=…` и дамп продолжается. Ничего в клавиатуру не пишет. Формат и разбор — в `docs/ajazz-guide.md` (раздел C).

> [!IMPORTANT]
> Эти команды идут через wsclx-канал `0xFF68`. На ревизии `0C45:8009` он **не отвечает**, поэтому почти все секции придут как `*_error=Protocol` (а `kbc remap --list` — с ошибкой чтения). **Это ожидаемый и уже известный результат**, а не поломка сбора. Ценность сохраняется для других ревизий (`0x800A`, `0x8099`) и новых прошивок.

### Шаг 3.6. Системная информация

```bash
lsusb
udevadm info --attribute-walk /dev/hidraw<номер> | grep -E "idVendor|idProduct|usage_page|interface_number" 2>/dev/null
```

Приложите вывод `lsusb` для `0C45:8009` (и содержимое uevent командного hidraw).

## 4. Что и куда прислать

Соберите в один файл/архив (или просто вставьте вывод в чат) следующие данные:

| # | Команда | Файл/секция |
|---|---|---|
| 1 | `kbc list` | `kbc_list.txt` |
| 2 | `kbc info <vid:pid>` | `kbc_info.txt` |
| 3 | `kbc probe <vid:pid>` | `kbc_probe.txt` |
| 4 | дамп конфига (F99) / батарея (Ajazz) | `f99_config_dump.txt` / `kbc_battery.txt` |
| 5 | дамп keymap Default+FN1 (F99, `0x83`) | `f99_keymap_default.txt`, `f99_keymap_fn1.txt` |
| 6 | дифф конфига до/после Caps/Num/Scroll (F99) | `f99_cfg_before.txt`, `f99_cfg_after.txt` |
| 7 | читаемая карта keymap (`kbc remap <pid> --list`, Default+FN1) — F99 и Ajazz | `12-keymap-list.txt` |

## 5. Важные предостережения

- **По умолчанию не запускайте команды записи** (`kbc save`, `kbc rgb --light-off/--light-on`, `kbc set-*`, `kbc time`, `kbc screen`) — основной сбор не меняет настроек клавиатуры. Исключение — флаг `--write-tests` (только для AULA F99; скрипт делегирует тесты в `f99-usb-rev.sh`, см. раздел 0 и `docs/f99-guide.md`, B2.10). Тесты охватывают T1–T6: config write, indicators boot, color table + self-define, keymap write, per-key color write, indicators config diff.
- **Не отключайте** клавиатуру во время `feature-get` — драйвер держит канал открытым.
- Если после команды клавиатура «переподключилась» (узлы hidraw исчезли на 1–2 сек) — это штатное поведение AULA на некоторых write. В обычном (read-only) сборе такого быть не должно; если вы запускали `--write-tests` — это ожидаемо, и данные после теста восстанавливаются скриптом.
- Данные клавиатуры исторические и к колонке «BT» отношения не имеют: **по Bluetooth (BT) проект ничего не обещает** — единственный живой канал батареи это 2.4G-ресивер.
